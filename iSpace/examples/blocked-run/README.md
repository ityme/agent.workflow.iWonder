# 阻塞运行

本示例说明阻塞语义。阻塞表示当前角色无法继续推进，不能用等待时间长来替代阻塞证据。

建议记录：

```json
{
  "result": "blocked",
  "blockers": ["缺少必要输入文件。"],
  "next_step": "请求上游补充输入或升级人工介入。"
}
```

预期 track 形态：

- 当前角色写入 `result.json`，`result` 为 `blocked`。
- 父级读取结构化结果后写入汇总进度事件。
- 如果进入人工介入，应保留阻塞证据和处理决定。

阻塞语义：

- 必须有证据。
- 必须说明缺失条件或权限边界。
- 状态机非法跳转也应 fail closed 并记录为阻塞。
